# Nova Render 与编辑器分工

2026-11-16 根据对话“精简重构 nova renderer 接口”中已确认的分工调整。当前上游正在整理第一批多实例与模型原始空间正式 API；这是进行中的工作，不代表已提交、发布或通过编辑器验收。状态快照及现有扩展映射见 `packages/render-contract/migration.json`。

## nova-render 提供

- 模型资源、共享网格/纹理、多实例提交、世界矩阵、渲染可见性与投影标记、原始尺寸和原点。
- 完整相机：透视/正交、FOV、近远裁剪、位置和完整朝向；视口矩形、宽高比和裁剪，后续渲染到纹理。
- 通用射线查询：稳定实例 ID、世界命中位置和距离、实例过滤；后续法线、primitive ID、BVH 等加速。
- 运行时材质参数、纹理和多材质槽；任意场景实例的 GPU 阴影、质量设置；雾效与环境贴图加载/清除。
- 可选 UI 回调、上下文初始化、窗口事件和退出策略。核心库可在关闭 UI 时使用。
- 双端一致的公开能力与匹配的原生 SDK / Web / shader 发布产物；按后端明确验证范围。

库内“场景”仅指渲染资源和实例集合，不承担编辑器项目格式、层级树、ECS 或编辑命令。现有补丁供上游参考，不要求按旧内部结构或旧接口名原样合入。

## nova-editor 保留

- 文档、层级与父子世界变换计算，节点命名、隐藏继承、锁定规则，主相机/活动光源的选择。
- 点选/框选、多选、gizmo、Local/World、吸附、表面摆放和堆叠规则。调用库的射线查询，编辑器决定过滤哪些对象。
- 材质面板、共享/独立副本、参数几何体、资产版本、导入和重建操作；库执行实时渲染与材质更新。
- 保存、ZIP、恢复、撤销/重做、场景 schema 兼容，以及 SDK 下载、版本锁定和升级验收。
- 布局、菜单、字体、快捷键、Esc 取消事务、工具切换和辅助体显示策略。库若提供调试绘制/轮廓能力，编辑器决定何时、如何使用。

## 接入顺序和验收

1. **多实例与原始空间（上游进行中）**：接入配对包中的正式 API；用现有多实例、源空间、拾取/摆放夹具验证原点、尺寸、世界变换与资源共享。原项目未标记 sourceSpace 时的归一化语义必须保留；接口参数由适配层转换，不为跟随 SDK 改写旧项目。
2. **完整相机与视口**：接入完整位置/朝向、FOV/裁剪与视口接口，替换 OrbitCamera 的场景相机过渡映射。保存字段迁移、导航、视图立方体和主相机预览由编辑器处理；上游交付前保留当前滚转/FOV限制。
3. **拾取**：替换底层查询，保留选择事务、辅助体排除、锁定与隐藏、吸附和堆叠策略；验证镜像/非均匀缩放、过滤前最近命中以及双投影。
4. **材质、场景阴影与雾效**：逐项替换运行时能力，保留材质版本与旧 GLB 项目恢复；原生/Web shader 与库一起升级，验证颜色空间、主相机、阴影和环境移除。

每一项必须是：获取并锁定候选发布包 → 在独立缓存及构建目录适配 → 静态检查、双端构建、相关数据/渲染回归、旧项目互通 → 更新已验证锁文件 → 移除被正式能力完全替代的补丁/基线。正式 API 的命名和版本号以上游实际交付为准，不提前写死 v0.1.1 或假定 capabilities 字段已存在。

只完成阶段1时，不得覆盖安装成缺少阶段2–4能力的 SDK。可在独立候选构建中先验收阶段1；主编辑器仍使用已验证快照，直至可整体验收，或上游提供覆盖剩余必需能力的配对候选包。不得将新版头文件、旧静态库或不同版本 Web/shader 混用。

## 当前过渡实现的处理

- 当前 local-dev SDK 及 `.nenv`/schema v4 功能保留；不立即删除已有能力，不写入 nova-v2 正在迭代的工作区。
- `nova-sdk.lock.json.extensions` 是历史快照标记，不是 nova-render 已承诺的正式 API 清单。扩展在 `migration.json` 全部标为由上游维护、尚未验收正式替代。
- CPU 阴影深度栅格化是 Metal/Web 过渡实现，不能据此声称 DX12/Vulkan 场景阴影已支持；GPU shadow pass 与算法实现归上游。
- 当前 CPU 三角形拾取无 BVH；当前多实例只覆盖静态不透明光栅，不能推导出多实例动画、透明或光追支持。
- 拆分 primitive 为单材质 GLB 是当前资产兼容策略，不作为长期唯一材质方案。上游材质 API 到位后适配新运行时，保留旧资产和历史恢复。
- `tools/sdk/patches/atmosphere.mjs` 等冻结为临时兼容补丁，不再作为编辑器长期独立渲染分支演进。新增底层能力先列入上游需求；接入正式包后逐项退役。
- 普通 `sdk:stage` 的覆盖保护继续有效；`sdk:verify` 同时检查当前每项扩展具有已记录的维护方与迁移阶段。正式下载器尚未实现，不能把分工调整称为依赖已迁移。
